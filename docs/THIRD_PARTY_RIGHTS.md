[Apache-2.0 section 4](https://www.apache.org/licenses/LICENSE-2.0) distinguishes supplying the license, file-carried change notices, retained applicable source notices and upstream NOTICE attribution. [MIT](https://opensource.org/license/mit) requires its copyright and permission notice with copies/substantial portions. Current LICENSE/NOTICE files, source headers and the mapping above supply the intended tip distribution. Legacy port/overlay docstrings already indicate changes; lack of a new standard header alone is not proof of a section 4(b) violation. However, the four historical snapshots just listed (including execution) contain only the Agent Lightning MIT and vLLM Apache license files, no VERL Notice.txt attribution, and no copyright/license text in these three module bodies. Merely choosing MIT for original lab code cannot replace upstream obligations.

[ASF application guidance](https://www.apache.org/legal/apply-license.html) allows one full license copy per distribution and says dormant branches need not be converted solely for ASF's historical 1.1-to-2.0 migration. [ASF's FAQ](https://www.apache.org/foundation/license-faq.html) describes file headers as useful when files detach from a license. Neither statement expressly clears this repository's initial publication of adapted legacy snapshots missing the mapped notices. ASF project policy is not substituted for the third-party license terms.

The concrete gap is **distribution of historical snapshots without the current accompanying attribution**, not uncertainty about all lab code. A full current clone includes the notices, but [GitHub's commit-specific archives](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives) contain the chosen commit's tree, not later files or the whole history. Such an archive of executed `5fb6adf` would omit current root NOTICE and its VERL attribution. The source links intentionally expose those historical versions. The evidence supports current-tip compliance work; it does not establish a safe historical-snapshot exception or additional permission.
