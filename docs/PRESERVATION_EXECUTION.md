## Recovery and diagnostics

The Hub ledger is updated with expected-parent revision guards. A lost spawn acknowledgement leaves `launching`; reconnecting refuses another launch. Inspect the durable worker ID/receipt and Modal call state. Never infer failure from laptop disconnect. After an ordinary failed non-scientific phase is diagnosed and its call is terminal, explicit `--recover-phase PHASE --diagnosis DESCRIPTION` can claim a bounded recovery attempt. Maximum two, no repeated identical diagnosis, no automatic scientific-run retry. Full failed receipts and conservative resource reservations remain. Hard termination or ambiguous invocation requires reconciliation; no clock-based claim stealing exists.

The public HF HTTP-client hook bounds outbound request bodies with framing allowance and turns retryable HTTP/network failures into a diagnosed stop. Xet is disabled before import so uploads cannot bypass that hook; this uses the installed SDK’s supported LFS transport. The counter is conservative accounting, not a cloud billing meter.

An interrupted transfer stays incomplete. Resume reads and hashes committed destination parts before reuse, checks source-manifest identity, and never overwrites committed files. A completed transfer is not resumed as a new upload; advance only after independent readback and qualification. Partial restores and conversion directories are retained and refused as fresh destinations. Choose a separately reviewed fresh recovery location within remaining space, never delete the partial attempt.

| Diagnostic | Required response |
|---|---|
| Source scope, exclusions, base/provenance, frozen hash or marker differs | Retain inventory; investigate identity/corruption; no transfer substitution |
| Destination revision conflict or foreign prefix member | Re-read immutable state and reconcile; never blind retry/overwrite |
| Destination byte mismatch, invalid bundle or incomplete scope | Backup remains unverified; no restore/evaluation |
| Unsupported layout, unequal aliases, native/config mismatch | Stop conversion; preserve source and failed output |
| Missing/wrong held-out cases/rewards | Preserve the evaluation; investigate, no preferred-score rerun |
| Native/export score or output differences | Retain all cases and inspect loading/conversion evidence before release; equality is not a scientific target |
| Capacity, budget or retry reservation exceeded | Stop new work; retain receipts and partial attempts |
| SDK failure | Report exception type/phase only; never log signed URLs, headers or raw credential responses |

A legitimate native/export difference can continue without rerunning evaluation after an actual investigation is recorded at `workflows/WORKFLOW/reviews/original-differences.json` (or `replication-differences.json`). The record must bind `comparison_sha256` to the complete comparison receipt and `export_manifest_sha256` to the converter result, and include `reviewer`, `reviewed_at`, `analysis`, `evidence_locations`, and disposition `no_conversion_or_loading_defect`. It cannot waive all-tensor equality. Keep this small release-visible review free of raw questions, answers and traces. Publication records the immutable review revision. Missing or mismatched reviews stop publication; the reviewed record is never generated from score equality alone.

The byte/receipt tests do not run real tensors or establish cloud integration. A successful local suite is not CI, a cold build, a disconnect/reconnect demonstration, backup verification, or release qualification.
